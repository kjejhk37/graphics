# Task: 테스트 인프라 잔여 항목 정리

## Purpose

지난 사이클(그래픽스 단위 테스트 환경 구성)의 리팩터 검사에서 `[DEFERRED]`로 남겨둔 2건을 처리한다.

1. `graphics_add_hlsl_shader()` 11회 호출의 반복 boilerplate를 데이터 목록 + 반복문으로 통합.
2. `OpenGLRenderer` 전용 동작 테스트 부재 — `DirectX9/11/12RendererTest`와 대등한 커버리지 추가.

## Requirements

- 리팩터 검사 원문 참고: `docs/archive/그래픽스_테스트환경_구성_20260811/review/그래픽스_테스트환경_구성_20260811_2058.md`

**항목 1 — 셰이더 등록 boilerplate 통합**
- `graphics/CMakeLists.txt`의 11개 `graphics_add_hlsl_shader(...)` 호출을 backend/entry/profile 4개 필드로 이루어진 데이터 목록 + `foreach` 루프로 대체한다.
- CMake는 네이티브 튜플/2차원 리스트가 없으므로, 필드 구분자를 무엇으로 할지(예: 세미콜론이 아닌 다른 구분자로 필드를 합친 뒤 파싱, 혹은 병렬 리스트 4개를 인덱스로 순회)는 전략 단계에서 확정한다.

**항목 2 — OpenGLRenderer 테스트 추가**
- 착수 전 `OpenGLRenderer.cpp`/`.h`의 실제 구현 상태(Initialize/RenderFrame이 실제로 동작하는지, 스텁 수준인지)를 먼저 확인해야 한다 — 브레인스토밍 단계에서 조사.
- `DirectX9/11/12RendererTest` 패턴(Initialize 성공, Resize+RenderFrame 생존, 인스턴싱 등)을 참고해 대등한 수준의 커버리지를 추가한다.
- OpenGL은 DirectX 9/11/12와 달리 별도의 디바이스 컨텍스트/확장 로딩 방식을 쓸 수 있어, 실제 테스트 환경에서 초기화가 가능한지 여부에 따라 범위가 달라질 수 있다.

- 두 항목 모두 완료 후 재구성/재빌드/`ctest` 전체 재실행으로 회귀 없는지 확인한다.
