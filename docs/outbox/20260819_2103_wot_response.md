# Response: ImageUI용 텍스처 로딩 공개 API

## Delivered Interface

- `renderer/IRenderer.h`에 추가:
  - `virtual void* LoadTexture(const std::string& filePath) = 0;` — 파일 경로 → `ImageUI`가 바로 쓸 수 있는 `void*` 핸들. 실패 시 `nullptr`(예외 없음).
  - `virtual void UnloadTexture(void* textureHandle) = 0;` — 로드된 텍스처 해제. 알 수 없는/이미 해제된 핸들을 넘겨도 안전(no-op).
- **실제 구현은 `DirectX11Renderer`뿐이다** — WOT의 기본/실사용 백엔드가 DirectX11인 것을 확인하고 범위를 그렇게 좁혔다(Deviations 참고). `DirectX9Renderer`/`DirectX12Renderer`/`OpenGLRenderer`는 `LoadTexture`가 항상 `nullptr`을 반환하는 스텁이다.
- 이미지 디코딩은 WIC(Windows Imaging Component) 기반 — PNG/JPEG/BMP 등 WIC가 지원하는 포맷을 전부 지원한다. 새 서드파티 의존성이 아니다(Windows SDK 시스템 컴포넌트).

사용 예시(WOT `IntroScene` 쪽 통합 시):

```cpp
void* textureHandle = renderer->LoadTexture("assets/textures/start_button.png");
if (textureHandle)
{
    ImageUI startImage(textureHandle, 128.0f, 128.0f, []() { /* 클릭 처리 */ });
    registry.Add(&startImage);
}
// ...
renderer->UnloadTexture(textureHandle);  // Scene 종료 시
```

## Compatibility

**backward-compatible** — 기존 `IRenderer` 사용 코드는 변경 없이 동작한다.

`IRenderer`에 순수가상함수 2개(`LoadTexture`/`UnloadTexture`)가 추가됐다 — `IRenderer`를 저장소 밖에서 직접 구현하는 코드가 있다면 컴파일이 깨지지만, 지난 응답(v0.1.0)과 동일한 이유로 WOT에는 영향 없다(WOT은 `IRenderer`를 구현하지 않고 `RendererFactory`의 결과물을 사용만 한다).

## Deviations from Request

- **DX9/DX12는 실제 구현하지 않고 스텁으로 남김**: 요청 문서는 OpenGL만 no-op으로 명시했지만, WOT의 `AppConfig.h`/`LaunchConfigStore.cpp` 기본값을 확인해보니 실사용 백엔드는 DirectX11뿐이었다. DX9는 아직 3D 모델 렌더링에서도 텍스처를 전혀 안 쓰고 있었고, DX12는 `ImGuiManagerDX12`의 SRV 힙이 폰트 전용 1슬롯 고정이라(그 파일에 이미 "실제 UI 개발 시 진짜 할당자로 바꿔야 한다"는 주석이 있었음) 제대로 구현하려면 별도 디스크립터 힙 설계가 필요한 큰 작업이다. DX9/DX12가 실제로 필요해지는 시점에 새 요청으로 확장하는 게 낫다고 판단했다.
- **텍스처/SRV 생성 코드가 이미 있다는 요청의 전제는 사실이 아니었다**: 큐브 모델 렌더링 파이프라인은 텍스처를 전혀 쓰지 않는다. 이번 응답은 "노출"이 아니라 "신규 구현"이다.

## Version

`v0.2.0` (v0.1.0에 추가 기능 — additive, breaking 아님).
