# Task: WOT 요청 — ImageUI용 텍스처 로딩 공개 API

## Purpose

지난 사이클(v0.1.0)에서 `ImageUI`가 `void* textureHandle`을 인자로 받는 형태로 나갔는데, WOT이 실제로 PNG 등 이미지 파일을 로드해서 그 핸들을 만들 방법이 없다.
`IRenderer`(또는 별도 인터페이스)에 파일 경로 → `void*` 텍스처 핸들 변환을 감싼 공개 API를 추가해서, WOT이 DirectX 타입을 직접 다루지 않고도 이미지를 로드할 수 있게 한다.

원본 요청 문서: `docs/inbox/20260819_2103_wot_request.md`. 이번 요청 브랜치는 최신 main(`609fc5c`, v0.1.0) 기준이라 stale 문제 없음.

## Author

Requester: WOT(`projects`) 저장소, `src/projects` 계층. (cross-repo 요청)

## User Draft

요청 원문의 기대 형태:

- `virtual void* LoadTexture(const std::string& filePath) = 0;` (시그니처는 graphics가 확정)
- 실패 시 동작(예외 vs nullptr)은 graphics 판단
- `UnloadTexture(void*)` 필요 여부도 graphics 판단
- `OpenGLRenderer`는 no-op만

## Requirements — 요청 문서의 전제 중 수정이 필요한 부분

요청 문서는 "`DirectX*Renderer` 내부적으로 3D 모델 렌더링용 텍스처/SRV 생성 코드가 이미 있을 것"이라고 추정했는데, 코드베이스를 확인한 결과 **사실이 아니다**.

- 현재 cube 모델 렌더링 파이프라인(`CreateBaselinePipeline` 등)은 position/normal/index 버퍼만 쓰고 텍스처를 전혀 쓰지 않는다.
- `ID3D11Texture2D`가 코드에 등장하는 유일한 곳은 스왑체인 백버퍼(`DirectX11Renderer::CreateRenderTargetView`)뿐 — 이미지 텍스처와 무관.
- `ImGuiManagerDX12`의 SRV 디스크립터 힙은 **폰트 아틀라스 1개 슬롯짜리로 고정**되어 있고, 코드에 이미 "여러 텍스처를 동적으로 할당해야 하는 사이클에서는 진짜 풀 할당자로 교체해야 한다"는 주석이 있다 — 이번이 바로 그 사이클이다.
- DX9는 SDK에서 D3DX9 유틸리티(`D3DXCreateTextureFromFile` 등)가 제거된 지 오래라, 이미지 디코딩부터 직접 해야 한다(D3DX 의존 불가).

따라서 이 요청은 "이미 있는 텍스처 로딩 코드를 공개 인터페이스로 노출"하는 작은 일이 아니라, **이미지 디코딩 + DX9/11/12 3개 백엔드용 텍스처/SRV 생성 파이프라인을 새로 만드는 일**이다.
