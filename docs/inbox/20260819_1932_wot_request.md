# Request: IntroScene용 2D UI 위젯 렌더링 계약 (Button/Progress/StringField/Label/Image)

## Requester

`World-of-Tank-imitation-Refactoring`(WOT) 저장소, `src/projects` 계층.

## Purpose

WOT은 이번 사이클에서 `src/projects/game`에 `IntroScene`(신규)을 만들고, 그 안에 Button/Progress/StringField/Label/Image 5종의 2D UI 위젯을 화면에 표시해야 한다.
WOT의 Core Development Principle("외부 라이브러리는 반드시 내부 wrapper로 감싸고, 다른 모듈은 직접 참조 금지")에 따라 `projects`는 `<imgui.h>`를 직접 참조할 수 없다 — 지금 `imgui.h`를 아는 파일은 `graphics/ui/directx{9,11,12}/ImGuiManagerDX{9,11,12}.cpp` 3개뿐이고, 이 경계를 유지한 채로 위젯을 그리려면 `graphics`가 위젯 렌더링 계약을 제공해야 한다.

기존 `IUiManager`(`graphics/ui/IUiManager.h`)는 ImGui 프레임 생명주기(`NewFrame`/`Render`/`Shutdown`/`HandleWin32Message`)만 책임지고 있어, 여기에 위젯별 그리기 메서드를 얹으면 책임이 섞인다고 판단했다. 그래서 별도의 위젯 계약/레지스트리 인터페이스 신설을 요청한다.

또한 `IRenderer`가 소유한 `IUiManager`가 지금은 완전히 private이라(`DirectX11Renderer::m_uiManager`), `projects`가 위젯을 등록할 진입점이 전혀 없다 — `IRenderer`에 위젯 레지스트리를 연결할 지점도 함께 필요하다.

## Needed Interface (요청 측 기대 형태 — 최종 설계는 graphics가 결정)

- `IUiBase` — 위젯 하나의 최소 렌더링 계약. 예: `virtual void Render() = 0;`
- `IUiElementRegistry` — 위젯 종류를 모르는 순수 레지스트리 계약. 예: `Add(IUiBase*)`/`Remove(IUiBase*)`/`RenderAll()`.
- `ButtonUI : IUiBase` — `ImGui::Button` wrapper.
- `ProgressUI : IUiBase` — `ImGui::ProgressBar` wrapper.
- `StringFieldUI : IUiBase` — `ImGui::InputText` wrapper.
- `LabelUI : IUiBase` — `ImGui::Text` wrapper.
- `ImageUI : IUiBase` — `ImGui::Image`/`ImGui::ImageButton` wrapper (텍스처 유무로 분기).
- `IRenderer`에 `IUiElementRegistry` 연결 지점 추가. 예: `SetUiElementRegistry(IUiElementRegistry&)`.
- `DirectX9Renderer`/`DirectX11Renderer`/`DirectX12Renderer` — 각자의 `m_uiManager->NewFrame()` ~ `Render()` 사이에서 등록된 registry의 `RenderAll()`을 호출하도록 배선.
- `OpenGLRenderer` — 이번 요청 범위에서는 위 신규 메서드의 **no-op 구현**만 있으면 된다(컴파일 통과 목적). 실제 ImGui/UI 배선은 OpenGL 백엔드가 실제로 필요해지는 시점으로 미뤄도 된다 — WOT은 지금 OpenGL을 쓰지 않는다.

`projects`가 상속해서 쓸 구체 위젯(`IntroStartButton : ButtonUI` 등)은 WOT 쪽에서 직접 만들 것이므로, 이 요청은 위 추상 계약까지만 필요하다.
