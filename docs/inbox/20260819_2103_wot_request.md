# Request: ImageUI용 텍스처 로딩 공개 API

## Requester

`World-of-Tank-imitation-Refactoring`(WOT) 저장소, `src/projects` 계층.

## Purpose

지난 요청(`docs/inbox/20260819_1932_wot_request.md`, v0.1.0으로 응답 완료)으로 받은 `ImageUI`(`textureHandle`을 `void*`로 받는 위젯)를 실제로 쓰려면, `projects`가 이미지 파일(PNG 등)을 로드해서 그 `void*` 핸들을 얻을 방법이 필요하다.

현재 `IRenderer`엔 `Initialize`/`RenderFrame`/`OnResize`/`Shutdown`/`HandleUiMessage`/`SetUiElementRegistry`뿐이고, 텍스처를 로드해서 핸들을 돌려주는 공개 API가 없다. `DirectX*Renderer` 내부적으로는 3D 모델 렌더링을 위해 이미 텍스처/셰이더 리소스 뷰(SRV) 생성 코드가 있을 것으로 추정하지만(모델 렌더링 경로), `projects`가 접근할 수 있는 공개 인터페이스가 아니다.

WOT의 Core Development Principle에 따라 `projects`는 DirectX 타입을 직접 다룰 수 없으므로, `IRenderer`(또는 별도 인터페이스)에 텍스처 로딩을 감싼 메서드가 필요하다.

## Needed Interface (요청 측 기대 형태 — 최종 설계는 graphics가 결정)

- 파일 경로를 받아 `ImageUI`가 바로 쓸 수 있는 `void*` 핸들을 돌려주는 메서드. 예: `virtual void* LoadTexture(const std::string& filePath) = 0;` (시그니처는 graphics가 확정).
- 로드 실패 시 동작(예외 vs `nullptr` 반환)은 graphics 판단에 맡긴다 — WOT은 어느 쪽이든 처리 가능.
- 텍스처 해제/언로드가 필요한지(예: `UnloadTexture(void*)`) 여부도 graphics가 판단 — 이번 사이클의 `IntroScene`은 앱 종료까지 텍스처 하나만 들고 있어 당장은 명시적 해제가 필수는 아니지만, 리소스 관리 원칙상 필요하다고 판단되면 추가해도 된다.
- `OpenGLRenderer`는 지난 요청과 동일하게 이번에도 UI 미지원 상태이니, no-op 구현만 있으면 된다.

보통(Normal) — `IntroScene`의 나머지 4종 위젯(Label/Button/Progress/StringField)은 이미 `main.cpp`에 배선·빌드·스모크 테스트 완료된 상태라, `ImageUI`만 이 응답을 기다리고 있다.
