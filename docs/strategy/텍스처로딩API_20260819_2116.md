# Strategy: WOT 요청 — ImageUI용 텍스처 로딩 공개 API

Cross-repo 의존성 검토: 전부 `graphics` 내부에서 완결된다. `platform`의 변경이 필요한 항목은 없어 전 항목 `[self]`.

## Checklist

- [x] `[self]` `renderer/WicImageLoader.h/.cpp` 작성 — WIC(`<wincodec.h>`) wrapper. 파일 경로(UTF-8 `std::string`) → RGBA8 픽셀 버퍼 + width/height. COM 초기화/해제를 내부에서 처리(호출부는 COM을 몰라도 됨).
- [x] `[self]` `renderer/IRenderer.h`에 `virtual void* LoadTexture(const std::string& filePath) = 0;` / `virtual void UnloadTexture(void* textureHandle) = 0;` 추가.
- [x] `[self]` `DirectX11Renderer`: `LoadTexture`(WIC 디코딩 → `CreateTexture2D` → `CreateShaderResourceView`, 실패 시 `nullptr`) / `UnloadTexture` 구현. 로드된 SRV는 `std::unordered_map<void*, ComPtr<ID3D11ShaderResourceView>>` 멤버로 보관해 수명 관리, `Shutdown()`에서 전부 해제.
- [x] `[self]` `DirectX9Renderer`/`DirectX12Renderer`: 스텁 구현 — `LoadTexture`는 항상 `nullptr` 반환, `UnloadTexture`는 no-op (Brainstorming Q2 — 실사용 백엔드인 DX11만 우선).
- [x] `[self]` `OpenGLRenderer`: 스텁 구현 (기존 패턴과 동일).
- [x] `[self]` `CMakeLists.txt`: `WicImageLoader.cpp` 소스 추가, `graphics_lib`에 `windowscodecs.lib` 링크 추가, `test_texture.png` 픽스처 복사 스텝 추가.
- [x] `[self]` 테스트용 이미지 픽스처(`tests/fixtures/textures/test_texture.png`, 4x4) 생성.
- [x] `[self]` 단위 테스트: `WicImageLoaderTest`(유효 파일 디코딩 성공/치수+픽셀값 검증, 존재하지 않는 파일 실패), `DirectX11RendererTest`에 `LoadTexture`/`UnloadTexture` 케이스 추가(성공 시 non-null, 실패 시 nullptr, 로드한 핸들을 `ImageUI`+`UiElementRegistry`로 실제 프레임 안에서 그려도 크래시 없음 확인, 알 수 없는 핸들 `UnloadTexture` 안전), DX9/DX12 스텁도 항상 `nullptr`/no-op 검증하는 최소 테스트 추가.
- [x] `[self]` 빌드 + 전체 테스트 통과 확인 — 45/45 통과 (신규 7개 포함).
- [x] `[self]` `docs/outbox/20260819_2103_wot_response.md` 작성 후 team_task_delegation Step 3 후속(커밋/merge/태그/브랜치 삭제).

## Verification Criteria

- `WicImageLoader` 외 다른 파일에서 `<wincodec.h>`/COM 텍스처 디코딩 API를 직접 호출하지 않는다(wrapper 경계).
- DX9/DX12/OpenGL의 스텁은 컴파일만 통과시키고 실제 동작은 하지 않는다는 것이 주석으로 명시되어 있어야 한다.
- 빌드 및 전체 단위 테스트 그린.
