# Task: WOT 요청 — IntroScene용 2D UI 위젯 렌더링 계약

## Purpose

`World-of-Tank-imitation-Refactoring`(WOT)의 `IntroScene`이 Button/Progress/StringField/Label/Image 5종 위젯을 화면에 표시해야 하는데, WOT의 "외부 라이브러리 직접 참조 금지" 원칙 때문에 `imgui.h`를 직접 볼 수 없다.
`graphics`가 위젯 렌더링 계약(추상 인터페이스)과 각 위젯의 ImGui wrapper 구현을 제공하고, `IRenderer`에 위젯 레지스트리를 연결할 진입점을 추가해서, WOT이 `imgui.h`를 몰라도 위젯을 등록/표시할 수 있게 한다.

이 사이클은 `team_task_delegation.md` Step 3에 따라 진행되는 cross-repo 요청 처리이며, 원본 요청 문서는 `docs/inbox/20260819_1932_wot_request.md`이다.
Step 3 스코프 규정에 따라 이번 사이클은 **추상 계약(인터페이스)까지만** 설계/구현한다 — WOT이 상속해서 쓸 구체 위젯(예: `IntroStartButton`)은 WOT 쪽에서 별도로 만든다.

## Author

Requester: WOT(`projects`) 저장소, `src/projects` 계층. (cross-repo 요청 — graphics 자체 사용자 요청 아님)

## User Draft

원본 요청의 기대 인터페이스 (최종 설계는 graphics가 결정):

- `IUiBase` — 위젯 하나의 최소 렌더링 계약 (예: `virtual void Render() = 0;`)
- `IUiElementRegistry` — 위젯 종류를 모르는 순수 레지스트리 계약 (`Add`/`Remove`/`RenderAll`)
- `ButtonUI`, `ProgressUI`, `StringFieldUI`, `LabelUI`, `ImageUI` — 각각 `IUiBase`를 구현하는 ImGui wrapper
- `IRenderer`에 `SetUiElementRegistry(IUiElementRegistry&)` 같은 연결 지점 추가
- DX9/11/12: `m_uiManager->NewFrame()` ~ `Render()` 사이에서 registry의 `RenderAll()` 호출하도록 배선
- OpenGL: 이번 스코프에서는 no-op 구현만 (컴파일 통과 목적, 실제 배선은 추후)

## Requirements

- 기존 `IUiManager`(ImGui 프레임 생명주기 책임)와 책임을 섞지 않는다 — 위젯 계약은 별도 인터페이스로 분리.
- `IRenderer::m_uiManager`는 현재 완전히 private — 위젯 등록 진입점이 없다는 문제를 해결해야 한다.
- SOLID/SRP, 외부 라이브러리 wrapper 격리, 단위 테스트 작성 등 graphics 자체 Core Development Principles(`agent_harness/CLAUDE.md`)가 요청 내용보다 우선한다.
