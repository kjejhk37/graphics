# Code Review: WOT 요청 — IntroScene용 2D UI 위젯 렌더링 계약

## Stage 1 — Quality Inspection

### Immediately Resolvable (해소 완료)

- [HIGH] `UiElementRegistry::RenderAll()`이 `m_widgets`를 직접 순회했다.
  - 위젯의 `Render()`(예: 클릭 콜백)가 자기 자신이나 다른 위젯을 registry에서 `Remove`하는 "self-destroying widget" 패턴(예: 닫기 버튼)을 쓰면, 순회 중 벡터가 재할당/erase되어 순회 중인 iterator가 무효화된다.
  - MSVC 디버그 STL은 이를 즉시 assert/crash로 감지한다 — 실사용에서도 undefined behavior.
  - **[해결 방안]**
    - `RenderAll()`이 `m_widgets`의 로컬 스냅샷 복사본(포인터만 복사하므로 비용 낮음) 위에서 순회하도록 수정.
    - `[RESOLVED]` — `ui/widgets/UiElementRegistry.cpp` 수정, 회귀 테스트 `UiElementRegistryTest.RenderAllToleratesWidgetRemovingItselfDuringRender` 추가, 통과 확인.
- [LOW] `DirectX9Renderer.h`/`DirectX11Renderer.h`/`DirectX12Renderer.h`의 클래스 주석(Notes)이 새로 추가된 `SetUiElementRegistry`/`RenderAll()` 배선을 설명하지 않았다.
  - `IRenderer.h`/`OpenGLRenderer.h`는 이미 설명을 포함해 일관성이 깨져 있었다(Comment Rules).
  - **[해결 방안]**
    - 세 헤더의 Notes에 `SetUiElementRegistry`가 `RenderFrame`/`RenderWithCommandList` 안에서 언제 호출되는지 한 줄씩 추가.
    - `[RESOLVED]` — 세 파일 모두 수정 완료.

### Needs Separate Handling (별도 처리 필요 — 자동 해소하지 않음)

- [MEDIUM] `ButtonUI`/`ImageUI`의 `onClick` 콜백이 실제로 호출되는 경로는 어떤 테스트에도 없다.
  - `UiWidgetsTest`는 생성 + `Render()` 호출이 크래시하지 않는 것만 검증한다 — 시뮬레이션된 클릭이 콜백을 실제로 트리거하는지는 검증하지 않는다.
  - ImGui의 클릭 판정은 여러 프레임에 걸친 `ImGuiIO` 마우스 상태(위치/버튼 down/up)를 필요로 하는데, 이 저장소의 기존 테스트 인프라(`ImGuiManagerDX*Test.cpp` 포함)에는 이를 시뮬레이션하는 헬퍼가 없다.
  - 이 헬퍼를 새로 만드는 건 이번 태스크가 개발한 범위를 넘어서는 별도 작업으로 판단해 자동으로 손대지 않았다.
  - 사용자 결정 필요: 별도 task delegation cycle로 "ImGui 입력 시뮬레이션 테스트 헬퍼"를 만들지 여부.

### 나머지 항목 (문제 없음)

- SOLID: 각 위젯/레지스트리 클래스가 단일 책임을 유지한다. `IRenderer`에 `SetUiElementRegistry`를 추가한 것은 기존에도 UI 관련 메서드(`HandleUiMessage`)를 이미 갖고 있던 선례와 일관된다.
- Library Isolation: `imgui.h`는 `ui/widgets/*.cpp`(위젯 wrapper 구현부)에서만 include된다. 헤더(`ButtonUI.h` 등)는 imgui 타입을 노출하지 않는다 — `ImageUI.h`도 `ImTextureID` 대신 `void*`를 받도록 조정해 이 경계를 지켰다(Deviations 참고).
- Comment Rules: 신규 클래스 전부 Author/Description/Input/Output/Notes/Date를 포함한다.
