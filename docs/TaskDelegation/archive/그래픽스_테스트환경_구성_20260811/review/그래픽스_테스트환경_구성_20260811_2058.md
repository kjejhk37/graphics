# Code Review: 그래픽스 단위 테스트 환경 구성

## Stage 1 — Quality Inspection

이번 사이클에서 새로 작성된 코드는 `graphics/CMakeLists.txt`(빌드 설정)와 `graphics/CLAUDE.md`, `.gitignore` 뿐이다.
`tests/*.cpp` 8+2개 파일은 전략 문서에서 승인된 대로 projects `tests/`의 원본을 그대로 복사한 것이라 이번 사이클의 "개발된 코드"가 아니며, 이번 검사 대상에서 제외한다.

- [RESOLVED] `wot_add_hlsl_shader()` CMake 함수(`graphics/CMakeLists.txt:177`)의 주석이 CLAUDE.md의 Comment Writing Rules(Author/설명/Input/Output/Notes/Date)를 충족하지 않는다.
  - 현재는 구현 세부사항에 대한 inline 주석(NAME_WE 함정, 제너레이터 표현식 제약)만 있고, 함수 목적/입출력/작성일을 요약하는 헤더 블록이 없다.
  - projects 원본(`World-of-Tank-imitation-Refactoring/CMakeLists.txt`)에도 같은 형식 누락이 있어 이식 과정에서 그대로 따라왔다.
  - **[해결 방안]**
    - 함수 정의 바로 위에 Author/Description/Input/Output/Notes/Date 필드를 포함한 헤더 주석을 추가한다.
    - 기존 inline 주석(NAME_WE, 제너레이터 표현식 제약)은 유지하되 Notes 필드에 요약해 통합한다.
  - **[결과]** 헤더 주석 추가 후 재구성/재빌드/`ctest` 재실행 — 28개 테스트 전부 Passed, 회귀 없음 확인 (2026-08-11).

**SOLID 원칙**: 해당 없음 — 이번 사이클에서 새로 작성된 C++ 클래스/함수가 없다(CMake 빌드 설정만 신규 작성).

**라이브러리 격리**: 위반 없음 — `graphics_lib`/`platform_lib`가 외부 라이브러리(imgui/ufbx/cgltf/nlohmann_json/tinyobjloader)를 FetchContent로 받아오는 것은 프로젝트 전체의 빌드 설정이며, 실제 라이브러리 사용은 기존 wrapper 클래스(`JsonDataStore`, `UfbxWrapper`, `CgltfWrapper`, `ImGuiManagerDX*` 등, 모두 platform/graphics 저장소의 기존 코드) 안에만 캡슐화되어 있다 — 이번 사이클에서 새로 뚫린 경로 없음.

**단위 테스트**: 충족 — 이번 사이클의 목표 자체가 테스트 이전이며, 28개 테스트(1단계 6개 + 2단계 22개) 전부 `ctest`로 통과 확인함.

**주석 규칙**: 위 LOW 항목 1건 제외하고 위반 없음.

### 해결 방식

- [LOW] 항목은 이번 사이클에서 작성된 코드에 대한 것이고 별도 범위 확장 없이 바로 고칠 수 있어 **즉시 해결 대상**이다.

## Refactor Inspection (검사만, 코드 수정 없음)

- [LOW] 11개 `wot_add_hlsl_shader()` 호출(`graphics/CMakeLists.txt:206-216`)이 backend/entry/profile만 다른 거의 동일한 형태로 반복된다.
  - 셰이더가 하나 추가/삭제될 때마다 거의 동일한 한 줄을 손으로 복붙해야 해서, 오타(entry point/profile 오기입)가 나도 CMake는 이를 감지하지 못하고 컴파일 시점에야 fxc 에러로 드러난다.
- [LOW] `wot_add_hlsl_shader()` 함수명과 `_wot_*` 임시 변수명이 소비 프로젝트(World-of-Tank-imitation-Refactoring, 약칭 WOT)의 네이밍 컨벤션을 그대로 이식해왔지만, graphics 저장소 자체에는 'WOT'을 가리키는 다른 개념이 전혀 없다.
  - graphics 저장소만 단독으로 처음 여는 개발자가 'wot_'가 무엇의 약자인지 저장소 내부 어디에서도 단서를 찾을 수 없어, 이 접두어를 오타나 잔재 코드로 오인할 수 있다.
- [LOW] `OpenGLRenderer`는 `RendererFactoryTest`에서 `dynamic_cast`로 타입만 확인될 뿐, `DirectX9/11/12Renderer`와 달리 `Initialize()`/`RenderFrame()` 동작을 검증하는 전용 테스트 파일이 없다(projects 원본부터 존재하던 공백 — 이번 사이클이 새로 만든 문제는 아님).
  - `OpenGLRenderer::Initialize()`나 `RenderFrame()`에 회귀가 생겨도 현재 테스트 스위트는 이를 잡아내지 못하고 그대로 통과한다.

이 3건은 검사 결과 보고이며 코드는 수정하지 않았다.
사용자가 처리할 항목을 선택하면 각각 새로운 task_delegation 사이클로 진행한다.
